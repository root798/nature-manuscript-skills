# 从研究问题到完整论文

本指南用于面向广泛科学读者的研究论文。字数、摘要形式、联系方式、数据与代码声明等，按目标文章类型及实际投稿要求核实。

## 开始前建立最小证据底稿

| 必填项 | 填什么 |
|---|---|
| 当前任务 | 新写、缩短、扩写、翻译、审阅、替换数字或调整结构。记下作者认可的版本、保护对象和本次可改的位置。 |
| 核心问题 | 哪一项既有认识尚不能回答哪个可观测问题？用一句能被另一种结果推翻的话写出预期。 |
| 决定性比较 | 谁与谁比、何时比、控制了什么、什么改变、基线为何公平。不同研究协议的数字放在各自范围内解释。 |
| 证据身份 | 数据版本、样本名册、独立单位、配对／排除条件、估计量、方向、单位、分母、区间及来源。标注已观察、估计、拟合、模拟、外推、尚待实验。 |
| 段落与图 | 每一项发现映射到具体段落、面板或表格。逐面板写出删去它会失去的独立证据。两项数字若来自不同版本或分母，分别命名。 |
| 极限与采用状态 | 哪个反例或不确定性改变解读？哪些属于项目限定、审稿人建议、作者已采纳裁决、仍有争议的提案？ |

把标题、各节问题和各段首句单独抄成反向提纲。逐段问“这一段比上一段多建立了什么”。两个段落仅用不同图型重述同一发现时，优先合并。一个段落同时塞入两个互不依赖的问题时，拆开并明确顺序。可先稳定核心 Results、数据及主图，再写引言、讨论和摘要。最终章节顺序应服务于读者理解。

具体设计小节标题、研究目标句及各段 topic sentence 时，用[这一份改稿示范](results-headings-and-openers.zh-CN.md)检验三者有没有互相抢答。

## 各节的职责与验收

| 部分 | 写法 | 验收问题 |
|---|---|---|
| 标题 | 指出科学对象、条件和经过支持的动作或发现。对只完成设计、结果尚未建立的工作，可使用问题式或描述式标题。 | 标题是否暗示因果、普适性、临床或实际有效性？主文是否真的支持这些词？ |
| 摘要 | 写领域已知与具体缺口、本文怎样区分解释、最重要结果、在什么边界内改变认识。术语首次出现要让陌生读者能读下去。 | 每个亮点数字能回到 Results。摘要单独阅读能说出比较双方、结论和意义。 |
| 引言 | 用原始研究公平交代已有工作。把缺口写成一个可回答的问题，而不是泛称研究很少。随后说明本研究怎样回答，避免把全部结果、方法或未来愿景提前塞入引言。 | 若删掉前两段宏观铺垫，问题是否更清楚？是否把尚未建立的现象写成 *this effect*？ |
| 研究设置（若需要） | 提前定义读者理解比较所需的样本、条件、术语与量。规模和设计事实可出现，尚未展示的效果另放 Results。 | 读者知道同一个对象被改变了什么，哪些条件保持不变。 |
| Results | 每小节围绕一个问题。用有力的比较、必要设计、诊断性实例、总体覆盖及真正影响解读的边界推进。未完成的实验只写问题、设计和预测。 | 逐段提取首句能复原发现链，每句强度能回到源表或面板。详见 [Results 指南](results-and-figures.md)。 |
| Discussion | 从已建立的结果推出对现有解释、测量、实践或后续试验的影响。指出哪个替代解释仍然成立，以及什么样的新证据可以区分。 | 区分本研究直接测量的事实、在现有证据内的解释、尚待验证的推广。避免逐图再报同一组数字。 |
| Methods | 给输入版本、纳入／排除、数据清洗、分组配对、测量过程、模型与检验、抽样单位、随机化、盲法、软件及随机种子等实际适用条件。区分预设决策与观察后选择。 | 另一位读者能重建样本和主要估计量，知道排除过哪些记录。 |
| 图注与表 | 结果图的图注标题用一句话给出图支持的发现，按面板定义点、线、色、形、单位、方向、区间和 n。纯设计图的标题交代设计。表格每行有清楚的实体，单位进表头，精度一致，说明缺失值。 | 单看图或表能复原对象与口径，回到正文知道为什么要看这里。 |
| 补充材料／扩展数据 | 放入支撑主张但在主文中影响阅读的敏感性检验、完整名册、推导与附加结果。主文需要解释的反例或关键不确定性不能只埋在补充材料里。 | 每个补充项目在主文有清楚落点，读者知道它支持哪一句。 |
| 结尾、投稿信与回复 | 用已经建立的最强结果和仍适用的边界收束，不以宣传语提升影响。审稿回复逐条写清原问题、实际改法、证据位置及未消除的不确定性。 | 没有宣称已完成未开展的试验，没有把不采纳的建议默默写进正文。 |

## 怎么学范文

从当前写作难点选择一段真正相关的原文，连看前后段、所引面板和图注。分别记录原文实际建立了什么，它如何通过对照建立这个结论，本稿是否具备支撑同一论证动作的证据。可以学“先给反常现象、再用对照排除一种解释”的结构。不要复用原文措辞、真实数据或未经检验的解释。

## 修订与最终交付

1. **先版本与范围。** 以作者最近确认的稿为底稿。记录固定的原图、标题、章节、删除项和外部材料。不同版本对同一条规则有冲突时，写清采用项和理由。新数据改变了科学事实时，先定位受影响的断言。
2. **再事实与论证。** 核正文、图面、图注、表格与来源中的同一量，区分打印在旧图上的数与按新口径得到的数。核引文原文是否支持所在句，书目信息真实不自动等于证据匹配。重构时用保留／移动／删除表记录位置与职责。
3. **再语言。** 按[英文用词指南](english-usage.md)逐句核主语、时态、指代、比较与术语。按[词表](word-policy.md)排除空洞强调和无依据因果。结果与图的关联以含义核实，不能靠字符串一致代替。
4. **最后验实际成品。** 若本次交付包括版式或 LaTeX，编译并打开最终导出的 PDF，核图号、面板、变量、字体、换行、段落和参考文献。区分“生成了文件”“检查了编译诊断”“看过实际页面”。许诺数据、代码、贡献或审批声明时，以实际材料为依据。
5. **按任务交付。** 局部改写给出明确落点和完整可替换段。审阅列具体问题、影响与建议。大修交差异摘要和待作者判断的事项。若缺源数据，给可验证部分及最小待核字段。不要把未经授权的线上操作、上传或投稿当作写作的一部分。
